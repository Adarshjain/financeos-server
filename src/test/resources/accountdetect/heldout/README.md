# Held-out account-detection corpus
Written independently from knowledge of how Indian banks, card issuers and payment apps phrase mail; the author did NOT read the engine (gmail/ main or test code) or any detect report.
- dev/ (16 mailboxes): visible to the engine developer. sealed/ (16 different mailboxes): only pass/fail counts are reported.
- One JSON per mailbox: {mailbox, today, mails[{id, from, subject, body, date, attachments[{filename, protected, pdfText?}]}], expected{accounts[], mustNotReport[]}}.
- expected.accounts: issuerDomain, last4, kind (CREDIT_CARD|DEBIT_CARD|ACCOUNT), variant, lifecycle (CLOSED|REPLACED|REPLACEMENT|ADDON|UPGRADED|null), lifecyclePartnerLast4, minEvidence (STRONG|WEAK, as a careful human would rate it).
- expected.mustNotReport: issuerDomain+last4 pairs that must never be reported (payee accounts, Aadhaar/mobile/reference digits, bank beneficiary accounts, other people's cards).
- variant is null where no mail/PDF ever names the product; generic words like "Platinum Debit Card" are not treated as a product variant.
- Amex last4 is the final four digits of the printed ending.
- All names, amounts and numbers are made up; bank names, domains and product names are real.
- Mails per mailbox: 110 to 361. Generated by a seeded script (reproducible); labels come from the generator config.
